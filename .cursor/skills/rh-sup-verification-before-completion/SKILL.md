# 完成前验证（Verification Before Completion）

## 概述

未经核实就声称完成，是**不诚实**，不是效率。

**核心原则：** 永远先有证据，再下结论。

**违反字面即违反精神。**

## 铁律

```text
NO COMPLETION CLAIMS WITHOUT FRESH VERIFICATION EVIDENCE
```

若本回合尚未运行验证命令，就**不得**声称通过。

## 门禁函数

```
在声称任何状态或表达满意之前：

1. 认定：哪条命令能证明该声称？
2. 执行：完整运行该命令（全新、完整）
3. 阅读：完整输出，检查退出码，统计失败数
4. 核实：输出是否支持该声称？
   - 否：带着证据陈述实际状态
   - 是：带着证据再下结论
5. 仅在此之后：再声称结果

跳过任一步 = 撒谎，不是验证
```

## 常见失败

| 声称 | 需要 | 不算数 |
|------|------|--------|
| 测试通过 | 测试命令输出：0 失败 | 上次跑过、「应该过」 |
| Lint 干净 | Lint 输出：0 错误 | 抽查、外推 |
| 构建成功 | 构建命令：exit 0 | Lint 过、日志「看起来好」 |
| Bug 已修 | 复现原症状：通过 | 代码改了、假定已好 |
| 回归测试有效 | 红-绿循环已核实 | 只跑过一次通过 |
| 代理已完成 | VCS diff 可见变更 | 代理回报「成功」 |
| 需求已满足 | 逐项对照清单 | 仅测试通过 |

## 红线 — 停下

- 使用「应该」「大概」「看起来」
- 核实前就表达满意（「太好了！」「完美！」「搞定！」等）
- 未验证就要 commit/push/PR
- 盲信代理成功报告
- 依赖**部分**验证
- 心想「就这一次」
- 累了想赶紧收工
- **任何**未运行验证却暗示成功的措辞

## 借口拆解

| 借口 | 现实 |
|------|------|
| 「现在应该好了」 | **去跑**验证 |
| 「我有信心」 | 信心 ≠ 证据 |
| 「就这一次」 | 没有例外 |
| 「Lint 过了」 | Lint ≠ 编译器 |
| 「代理说成功」 | **独立**核实 |
| 「我累了」 | 累不是理由 |
| 「抽查够了」 | 抽查证明不了什么 |
| 「换种说法就不算规则」 | 精神重于字面 |

## 关键模式

**测试：**

```
✅ [运行测试命令] [见：34/34 通过] 「全部通过」
❌ 「现在应该过了」/ 「看起来对」
```

**回归测试（TDD 红-绿）：**

```
✅ 编写 → 运行（过）→ 撤回修复 → 运行（必须失败）→ 恢复 → 运行（过）
❌ 「已写回归测试」（未做红-绿核实）
```

**构建：**

```
✅ [运行构建] [见：exit 0] 「构建通过」
❌ 「Lint 过了」（Lint 不检查编译）
```

**需求：**

```
✅ 重读计划 → 建清单 → 逐项核实 → 汇报缺口或完成
❌ 「测试过了，阶段完成」
```

**代理委派：**

```
✅ 代理报成功 → 看 VCS diff → 核实变更 → 汇报真实状态
❌ 盲信代理报告
```

## 为何重要

来自 24 条失败记忆：

- 协作伙伴说「我不信你」— 信任破裂
- 未定义函数上线 — 会崩
- 缺需求就上线 — 功能不完整
- 假完成浪费时间 → 返工重定向
- 违背：「诚实是核心价值。撒谎就会被换掉。」

## 何时适用

**在以下之前永远适用：**

- **任何**成功/完成的变体声称
- **任何**满意表达
- **任何**对工作状态的正面陈述
- 提交、建 PR、标任务完成
- 进入下一任务
- 再委派给代理

**规则覆盖：**

- 原话与转述、同义词
- 暗示成功的表达
- **任何**暗示完成/正确的沟通

## 结论

**验证没有捷径。**

运行命令。读输出。**再**声称结果。

没有商量余地。
